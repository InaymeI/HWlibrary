# Проверка клиента API — 0.5.8

База по умолчанию: `https://education.maximumtest.ru`. Авторизация — только
Cookie, без добавления Bearer-токена. Для локальных тестов база переопределяется.

| Назначение | Метод и путь | Проверка |
|---|---|---|
| Список уроков/блоков предмета | GET `/api/v3/student/education-groups/{course_id}` | `perPage=50`, далее `lastKnownId` внешнего узла; `page=N` не используется |
| Раскрытие блока/урока | GET `/api/v3/student/education-groups/{course_id}/structures/{node_id}` | В URL внешний id структуры, не entity lesson id |
| Домашка и её дерево | GET `/api/v1/content/practice/curriculumsubject/{subject_id}` | subject id из блока практики |
| Задания раздела | GET `/api/v1/content/practice/curriculumsubject/{subject_id}/knowledgebase/{kbs_id}/{mode}/tests` | online/offline/aftertheory; пустой режим не прекращает поиск |
| Отправка ответа | POST `/api/v1/content/practice/curriculumsubject/{subject_id}/tests/{test_id}` | Только `lessonId` (строка entity id), `attaches: []`, `answer: [...]`, `spentTime: 45–90` |

POST: не более трёх попыток при временных ошибках, задержка 400 мс; 4xx кроме
429 не повторяются. Массовая отправка прерывает дальнейшие задания при
401/403/429. Между заданиями используются обычные случайные паузы синхронизации.
Ответы type5 строятся отдельно для каждого поля с выбором допустимого варианта.

## Исправленные проблемы

1. Новый импорт объединял cookies со старыми. Теперь это полная замена.
2. 403 безосновательно назывался истечением сессии. Теперь он отделён от 401.
3. Автоматические редиректы requests могли перестраивать Cookie из jar, где
   импортированные cookies без домена сосуществовали с серверными того же имени.
   Сохранение учитывало только конечный ответ. Теперь редиректы GET выполняются
   явно, строго в том же origin, с новым каноническим заголовком на каждом шаге
   и учётом ротации на промежуточных ответах. Cookie jar очищается перед запросом.
4. Cookies из ошибочных ответов могли перезаписывать рабочие значения. Теперь
   ответы с кодом >=400 не меняют сохранённый набор; пустые значения не заменяют
   импортированные. Намеренное удаление сессии выполняется кнопкой очистки.
5. HTML с HTTP 200 автоматически считался страницей входа. Теперь клиент
   сообщает формат и статус, а не заявляет, что причина точно в сессии.

Ошибки показывают метод/путь/статус без query-параметров, значений Cookie и тела
ответа сервера. POST-редирект не повторяет изменяющий запрос, редирект на другой
origin не получает секретов. Ограничение — не более пяти переходов GET.

## Границы проверки

Проверки выполняются на локальном fake-server и синтетических HTTP-ответах:
контракты всех путей, параметры, тело POST, ограничения попыток, импорт и
ротация Cookie, редиректы, 401/403/HTML, глубокая загрузка и сохранность SQLite.
Реальные cookies из переписки не использовались и в файлы не записывались.
Это не подтверждение совместимости с текущим закрытым сервером на конкретной
пользовательской сессии. Если сервер продолжит отказывать, нужны точный метод,
путь и HTTP-статус из нового сообщения, а не публикация cookies.
